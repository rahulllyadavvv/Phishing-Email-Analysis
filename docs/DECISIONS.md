# Decisions

## P0.1: Project scaffold

- Build backend: setuptools. Packages found automatically: `phishlens*`, `api*`, `ui*`.
- `api/` and `ui/` get `__init__.py` files so they can be imported as packages.
- Empty directories (`data/`, `scripts/`, `tests/fixtures/`, `samples/`, `quarantine/`,
  `reports/`, `phishlens/reporting/templates/`) each have a `.gitkeep`. `samples/`, `quarantine/`
  and `reports/` are gitignored, so they are only created locally.
- Ruff: line length 100, target py311, rules E/F/W/I/B/UP. Excluded: `autopilot.py` and
  `progress.py` (autopilot tooling, not project code) plus the runtime data folders.
- pytest: `testpaths = ["tests"]`, `asyncio_mode = "auto"`. With zero tests pytest exits with
  code 5 ("no tests collected"). This is the expected result for P0.1.
- No version pins for dependencies yet. Pins can be added once the analysis code needs them.
- `.env.example` has sample local defaults for `REDIS_URL` and `DATABASE_URL`. All secrets are left blank.

## P0.2: Shared data models

- Fixed value sets are `StrEnum`s: `Severity`, `UrlSource`, `IOCType`, `CaseType`, and
  `VerdictLabel` (`clean` / `suspicious` / `malicious`, matching the report badges in PROMPTS.md).
  `IOC.verdict` stays a free `str | None` because reputation services use different words.
- Byte fields (`Attachment.data`, `ParsedEmail.raw_bytes`) use `Field(exclude=True, repr=False)`.
  They never appear in `model_dump()`, JSON output or repr. After a JSON round trip they are `b""`.
- `AnalysisReport.email` reuses `ParsedEmail` rather than a separate summary model. The byte
  exclusion already makes it a summary without raw bytes. `file_info` is an `Attachment`.
- `ParsedEmail.headers` is `list[tuple[str, str]]`, serialized as `[name, value]` pairs.
- `reply_to` is a list of `Address` (Reply-To can hold several addresses). `return_path` and
  `sender` are single optional addresses.
- `Finding.id` is checked against a snake_case regex. `Verdict.total_score` must be 0-100 and
  `confidence` must be 0.0-1.0. `Verdict` is optional on `AnalysisReport` so a partly built report
  can still be valid.
- All models use `extra="forbid"` so typos in field names fail fast. `created_at` defaults to
  the current UTC time.

## P0.3: Config and CLAUDE.md

- API keys (and `PHISHLENS_API_KEY`) are `SecretStr | None` so they never appear in repr, logs or
  `model_dump()`. `CAPE_BASE_URL` is a plain `str | None`, because it is a URL and not a secret.
- `env_ignore_empty=True`: blank values in `.env` (as in `.env.example`) fall back to the defaults.
  This also means `UPLOAD_FILES_TO_VT=` means `false`.
- `TRUSTED_*` lists are comma-separated strings. They are split, stripped and lower-cased into
  `list[str]` (using `NoDecode` so pydantic-settings does not try to parse them as JSON).
- `Settings.is_enabled(service)` / `configured_services()` use a `SERVICE_FIELDS` map
  (virustotal, abusech, google_safebrowsing, urlscan, abuseipdb, hybrid_analysis, cape, llm).
  An unknown service name raises `KeyError`, because that is a programming error.
- `get_settings()` uses `lru_cache(maxsize=1)`. Tests call `get_settings.cache_clear()`.
  `.env` is read relative to the current working directory. `extra="ignore"` so that unrelated
  variables in `.env` do not break startup.
- Rate-limit and cache TTL settings are not added yet. P4.1 will add them to config.
- The CLAUDE.md commands for the API and UI (`uvicorn api.main:app`, `streamlit run ui/app.py`)
  name modules that later phases will create.

## P0.4: Synthetic test fixtures

- The fixtures are generated by `scripts/make_fixtures.py` and committed. The output is
  deterministic (fixed Date, Message-ID, MIME boundaries and zip timestamps).
  `tests/test_make_fixtures.py` checks that the committed files match the generator byte for byte.
- `labels.yaml` is generated from the same table as the fixtures. Each entry has `verdict`
  (`clean` / `suspicious` / `malicious`) and `expected_signals`. The signals are only descriptive
  hints. They are not binding finding IDs, and later phases may map them to real finding IDs.
- Verdict choices: `zip_attachment` is `clean` (an aligned sender and a harmless text file).
  `password_zip`, `tracking_pixel`, `qr_code`, `display_name_trick` and `duplicate_from` are
  `suspicious`. The rest are `malicious` except `clean_newsletter`.
- Real brand domains appear only where the spec requires them: `microsoft.com` in the spoofed
  From, `paypal.com` as link text and `company.com` inside a display name. `zetatech.xyz` is used
  as the spec says. Every link target uses `.example`. Every IP is in a documentation range.
- The encrypted zip uses traditional PKWARE ZipCrypto, written by hand, because `zipfile` cannot
  write encrypted archives. The entry is stored (not compressed) and the fixed header bytes keep
  it deterministic.
- The duplicate `From` fixture uses a `compat32` `Message`, because `EmailMessage` rejects a
  second `From` header.
- The HTML smuggling attachment wraps the Blob / `createObjectURL` / `download` pattern in a
  function that is never called, and it has no `click()`. The embedded data is harmless base64 text.
- The script builds the EICAR string from pieces, so the script file does not contain the full
  signature. It does appear, base64-encoded, in `eicar_attachment.eml`. Local antivirus may flag
  or quarantine that file.
- The QR code is generated with `segno` (pure Python, added to the `dev` extras). `pyyaml` was
  added to the main dependencies because the YAML data files need it.
- Serialization uses LF line endings (the `email` default). Mail clients and editors accept them.

## P1.1: Email loader

- Detection uses only the content. The file extension and `filename` are never trusted, and
  `filename` only appears in error messages.
- `.eml` detection: every line up to the first blank line (checking at most 50 lines / 64 KB) must be
  an RFC 5322 header field or a folded continuation line. There must be at least two fields, and one
  of them must be a common mail header (From, Sender, Reply-To, Subject, Received, Return-Path,
  Message-ID, MIME-Version, Delivered-To). A UTF-8 BOM, leading blank lines and an mbox `From `
  separator line are allowed. If a NUL byte is present, the input is not an email.
- `.msg` detection: the data starts with the OLE signature and `extract_msg.openMsg` opens it as a
  message type that has `asEmailMessage`. Other OLE files (`.doc`, `.xls`, corrupt files, other
  MAPI types without `asEmailMessage`) load as `"file"`.
- Conversion uses extract-msg's own `asEmailMessage()` (headers, plain/HTML bodies, attachments,
  embedded messages), serialized with `email.policy.default`. If a message is recognized but
  conversion fails, the loader raises `MsgConversionError`. It is not silently treated as a file.
- `load_input` must return a 2-tuple, so the missing-transport-headers warning is carried inside
  the converted bytes as the header `X-PhishLens-Parse-Warning: msg_no_transport_headers: ...`.
  The parser (P1.2) should move this header into `ParsedEmail.parse_warnings`.
- Size limit: new setting `MAX_INPUT_SIZE_MB` (float, default 25, must be > 0). Inputs over the
  limit raise `InputTooLargeError`. For paths, the size is checked with `stat()` before the file is read.
  `LoaderError` (a `ValueError`) is the base class for loader errors.
- extract-msg cannot write `.msg` files and no `.msg` fixture exists, so the `.msg` tests mock
  `extract_msg.openMsg`. The corrupt-OLE test uses the real library.

## P1.2: Header and address parsing

- Entry point is `parse_headers(raw: bytes) -> ParsedEmail`. It fills `headers`, the address
  fields, `subject`, `date`, `message_id`, `raw_bytes`, `sha256` and `parse_warnings`. Later
  parser steps fill in the bodies, Received chain and attachments.
- Header values are decoded with `policy.default.header_fetch_parse` on `msg.raw_items()`, so
  duplicates and the original order are kept. Folded values are unfolded. If decoding raises, the
  parser falls back to `email.header.decode_header`, and after that to the raw unfolded text.
- Warnings are `"<code>: <detail>"` strings. The codes are `missing_from`, `empty_from`,
  `multiple_from_headers`, `multiple_from_addresses`, `display_name_contains_email`,
  `header_decode_error` (an exception, or U+FFFD in the decoded text) and `header_defect`
  (defects reported by the `email` package, such as an unknown charset).
- `display_name_contains_email` is checked on From, Sender and Reply-To. It is not raised when the
  address in the display name matches the real address (case-insensitive), because some mail
  clients use the address itself as the display name.
- `from_addrs` holds the addresses from every From header, in order. `sender` and `return_path`
  take the first address. `Return-Path: <>` (null sender) gives `return_path = None`.
- The loader's `X-PhishLens-Parse-Warning` header moves into `parse_warnings` and is removed from
  `headers`.
- `org_domain` uses `tldextract` with the bundled public suffix snapshot
  (`suffix_list_urls=()`, no cache dir), so it never uses the network. Domains without a known
  public suffix (reserved `.example` / `.test`, single labels) fall back to the last two labels.
  IP literals are returned unchanged. `domain` is lowercased. The local part is kept as written.

## P1.3: Received chain

- Entry points: `parse_received(value) -> ReceivedHop` (one header),
  `parse_received_chain(values) -> (chain, warnings)` (values in header order, newest first) and
  `received_chain_from_headers(ParsedEmail.headers)`. The chain is returned **oldest first**. The
  `ReceivedHop` docstring in `models.py` said "newest first" and was changed to match. Filling
  `ParsedEmail.received_chain` is left to the parser step that puts the parts together.
- The header is split at the last `;` into the clauses and the timestamp. Clause keywords (`from`,
  `by`, `via`, `with`, `id`, `for`) only count outside parentheses, so a comment such as
  "(Authenticated by ...)" does not start a `by` clause. `from_host` is the HELO name (the first
  token after `from`). It is `None` when the HELO is a bracketed IP literal.
- The IP is taken only from the `from` clause. Bracketed parts (`[1.2.3.4]`, `[IPv6:...]`) come
  first, then any bare token that parses as an IP. IPv4-mapped IPv6 addresses are turned into
  IPv4. Timestamps with no zone are treated as UTC so they can be compared.
- Warning codes: `received_no_ip` (every hop with no parsable IP, including `by`-only local
  hops) and `received_out_of_order` (a hop's timestamp is strictly earlier than the timestamp of
  the last earlier hop that had one). There is no clock-skew tolerance.
- `originating_external_ip(chain, trusted_internal_hosts)` returns an IP string. It walks from
  the newest hop back towards the sender and returns the first hop that is not internal. A hop
  is internal when its IP is private, loopback, link-local, multicast, reserved, unspecified or
  CGNAT, or when its IP or `from` host matches `trusted_internal_hosts`. That list can hold IPs,
  CIDRs, host names or domains, and a domain also matches its subdomains. Walking from the
  newest hop means a forged older hop cannot become the result. The result is the IP that handed
  the message to our infrastructure. Without trust config, a public IP on our own MX would be
  returned.
- Documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 2001:db8::/32) count as
  **external**, even though Python's `ipaddress` calls them private. This is because the
  synthetic fixtures use them in place of public IPs.
